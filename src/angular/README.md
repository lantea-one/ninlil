# Ninlil admin console

The Angular admin console for Ninlil: every DNS, DHCP, identity, and settings resource the REST
API exposes, a live dashboard fed by the SignalR event hub, and self-service account security.

It is a completely separate npm workspace from the .NET solution in `src/dotnet/`; the only thing
the two share is the OpenAPI document the typed API client is generated from. In production it is
not served on its own: `Ninlil.Web` builds it and serves it from the same process and port as the
REST API (see the repository's main `README.md`).

## Commands

| Command                                   | Does                                                                           |
| ----------------------------------------- | ------------------------------------------------------------------------------ |
| `npm ci`                                  | Installs the exact dependency versions in `package-lock.json`                  |
| `npm start`                               | Development server on `http://localhost:4200/` (point it at a running backend) |
| `npm run build`                           | Regenerates the API client, then builds the production bundle into `dist/`     |
| `npm run lint` / `npm run lint:fix`       | ESLint (flat config, `angular-eslint`)                                         |
| `npm run format:check` / `npm run format` | Prettier                                                                       |
| `npm test`                                | Jasmine/Karma unit tests in headless Chromium                                  |
| `npm run fetch:openapi`                   | Re-fetches `openapi/swagger.json` from a locally running backend               |

**Requirements**: Node.js with npm, a Java runtime (the OpenAPI generator is a Java tool), and
Chromium or Chrome for the tests — set `CHROME_BIN` if it is not found automatically, e.g.
`CHROME_BIN=/usr/bin/chromium npm test -- --watch=false --browsers=ChromeHeadlessNoSandbox`.

`npm run lint`, `npm run format:check`, the build, and the test suite are all pipeline gates. With
only Docker installed, `docker buildx build --target test-admin-console .` from the repository root
runs the same checks the pipeline does.

## The generated API client

`src/app/api-client/` is generated by `openapi-generator-cli` (the `typescript-angular` generator)
from the committed `openapi/swagger.json` snapshot, and is never edited by hand. `npm run build`
regenerates it automatically (its `prebuild` step), so a build never needs a running backend or
network access. When the backend's REST surface changes, refresh the snapshot yourself with
`npm run fetch:openapi` against a running backend and commit it alongside the change.

## Conventions

- **Angular 22, standalone components, signals-based state, zoneless** — there is no `zone.js`,
  so nothing may depend on zone-based change detection.
- **CoreUI for Angular** is the component library. Its compiled CSS is loaded globally, layered
  with this app's own catalog of five palettes × light/dark themes in `src/styles/themes/`, both
  driven by `ThemeService` setting `[data-coreui-theme][data-ninlil-palette]` on `<html>`.
  `src/styles/_tokens.scss` defines the spacing scale (`--ninlil-space-*`), type scale
  (`--ninlil-font-size-*`, 14px base), table density, and form/card widths — use those tokens
  instead of ad hoc values in a page's own styles.
- **Every page is lazy-loaded** (`loadComponent` in `app.routes.ts`); only the app shell and the
  Forbidden page are eager. An eager `component:` import pulls that page and everything it
  imports back into the initial bundle.
- **Feature-based folders**: `core/` (singleton services, guards, interceptors), `shared/`
  (cross-feature components), `layout/` (app shell, Forbidden page), `features/<name>/` (one folder
  per page, split further as it grows), `api-client/` (generated).
- **Naming**: kebab-case with a type suffix (`*.component.ts`, `*.service.ts`, `*.guard.ts`,
  `*.model.ts` for grouped data shapes, `*.util.ts` for pure helpers), one exported artifact per
  file, and no hand-written barrel `index.ts` files.
- **TypeScript strict mode** is on.
- **TSDoc on every public service, guard, interceptor, and component**, explaining _why_, to the
  same depth as the backend's XML doc comments.
- **Tests stay on Jasmine/Karma** rather than the CLI's newer Vitest-based default, as a
  deliberate choice; Karma runs headless and unsandboxed (`ChromeHeadlessNoSandbox`, see
  `karma.conf.js`) so it works in CI and in containers.
- **`@for` over a `FormArray` whose rows can be removed**: track the `FormGroup` instance
  (`track row`), not `$index`, or a native `<select>` in a later row can keep showing a removed
  row's selection.
- **Selected `<option>` inside `@for`**: mark it with `[selected]` on the `<option>` itself. A
  `[value]` binding on the `<select>` runs before the options exist and silently selects nothing.
