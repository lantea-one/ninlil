A TSIG key authenticates zone transfers (AXFR/IXFR) and RFC 2136 dynamic updates -- it has no other use in Ninlil. Saving one here doesn't attach it to anything by itself: open the zone that needs it from the Zones list and pick this key by name from its own TSIG Key selector (Security section). The secondary server or dynamic-update client on the other end needs the identical secret configured too, or authentication fails.

HMAC-SHA256 is the default and suits most clients. Pick the algorithm the other end is configured with (BIND's key statement names it): HMAC-SHA1, HMAC-SHA384 and HMAC-SHA512 are supported too. HMAC-MD5 is not. Key names are stored in lowercase.
