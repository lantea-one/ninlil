@if (form.controls.isDnssecSigned.value) {

This records the algorithm this zone's keys are meant to use -- the algorithm each key actually signs with is chosen individually when it's generated on the DNSSEC Keys page (see that page's own Algorithm hint for the full comparison of RSA/ECDSA/EdDSA choices). Keep this selection matching whatever you actually generate there.

NSEC proves a name doesn't exist by chaining every real owner name in the zone together in sorted order, each record pointing at the next. That's cheap, but it also means anyone can walk the chain record by record and read out the zone's entire contents, name by name, including ones nobody ever queried for -- "zone walking." NSEC3 proves the same non-existence without exposing real names: it hashes each owner name (salted, and re-hashed the number of times set below) before chaining those hashes instead, so walking the chain only yields hash values, not the names behind them, at the cost of the extra hashing work on every signing pass and every response. Choose NSEC3 whenever the zone holds names an operator would rather not have openly enumerable; plain NSEC is simpler and cheaper when the zone's contents aren't sensitive either way.
