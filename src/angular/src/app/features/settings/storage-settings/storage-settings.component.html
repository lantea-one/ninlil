Schedules a switch to a different database engine. Nothing changes now: Ninlil saves the request, and at its next start it copies all its data from the current database into the target and then uses the target. Restart Ninlil yourself to apply it. You can cancel a pending switch until then.

The copy takes every table, the query log included. A failed copy leaves the current database as it was and Ninlil keeps using it; the last outcome above says what happened.

Warning: if the target database already holds Ninlil data, the copy replaces it.

Which settings decide the engine matters. When the runtime configuration file decides, Ninlil points it at the target itself. When environment variables decide (the usual case with Docker), Ninlil cannot change them: after you schedule the switch, set NINLIL_STORAGE_ENGINE and NINLIL_STORAGE_CONNECTION_STRING to the target and restart. The copy runs at the first start that points at the target. The old database stays as it was and is not updated afterwards.

MongoDB cannot be a source or target of a switch. Switching is refused while a read replica or a cluster setting is configured: remove it, switch, then configure it again.
